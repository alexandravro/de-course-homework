# Домашнє завдання — Заняття 12: Структуровані дані у Spark. Частина 1

## Що робимо

Пишемо перший справжній **PySpark pipeline** на даних **GitHub Archive**: явна схема
читання, сплющення вкладених структур, правила якості, похідні колонки, три різні
marts (агрегат, top-N через window function, broadcast join) і запис у Parquet.
Це міст від L02 (Polars) і L03 (SQL/DuckDB) до Spark: «ті самі операції, розподілене
виконання».

Усе — через **DataFrame API**. SparkSQL і dbt будуть у L13 на цих самих даних.

- **Специфікація:** [`SPEC.md`](SPEC.md) — головний документ, контракти й контрольні числа.
- **Ваш код:** [`job.py`](job.py) — десять функцій із `NotImplementedError`.
- **Дані (в репозиторії):** [`data/landing/`](data/landing/) — 3 годинні зразки.

## Передумови

Потрібні лише `uv` і Java. Перевірте: `java -version` (підійде 17).

## Структура

```
homework/                    # ← ТУТ ВИ ПРАЦЮЄТЕ
├── SPEC.md                  # специфікація — контракти й контрольні числа

    └── test_outputs.py      # перевірки артефактів у data/output/
```

**Де писати код:** лише в десяти функціях `job.py`, позначених `NotImplementedError`.
`build_spark`, `read_raw` і `main` міняти не треба.

## Як запустити

Усі команди — з кореня `homework/`.

```bash
# швидкий цикл: unit-тести функцій, job запускати не треба
uv run pytest tests/test_functions.py

# повний прогін pipeline — пише у data/output/
uv run python job.py

# перевірки записаних артефактів
uv run pytest tests/test_outputs.py

# або все одразу
./verify.sh
```

## Як підходити

1. **Ідіть за `SPEC.md` зверху вниз.** Кроки залежать один від одного: `flatten` →
   `clean` → `with_derived`, потім marts, і `write_outputs` останнім.
2. **Тримайте відкритим `tests/test_functions.py`.** Він написаний до вашого коду і
   читається як приклади: видно очікувані колонки, типи й поведінку на NULL-ах.
   Кожна функція перевіряється незалежно, тому можна робити кроки не по порядку.
3. **Спочатку unit-тести, потім job.** Повний прогін Spark займає десятки секунд,
   unit-тести — секунди. Ганяйте job тоді, коли функції вже зелені.
4. **Звіряйтеся з checkpoint** у `SPEC.md`. Поки число не збіглося — трансформація
   ще не та.
5. **Дебаг:** `df.printSchema()`, `df.show(5, truncate=False)`, `df.explain("formatted")`.
6. **Помилка вилітає не там, де написана.** Spark лінивий: друкарська помилка в назві
   колонки впаде на `count()`, а не на `filter()`. Дивіться на перший рядок трейсу
   з вашим файлом, а не на початок Java-стека.
